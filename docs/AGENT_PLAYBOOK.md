# دليل تنفيذ المهام

هذا الملف يشرح طريقة العمل فقط؛ مصدر المهام هو docs/EXECUTION_PLAN.md.

## خطوات كل جلسة

1. افحص git status --short واحفظ التغييرات الموجودة خارج المهمة.
2. نفّذ أول مهمة غير مكتملة فقط، وراجع نصها وشرط إنجازها.
3. اقرأ الملفات المرتبطة بالمهمة والاختبارات المجاورة.
4. نفّذ أصغر تغيير يحقق المهمة، مع إبقاء Flutter وSupabase متوافقين.
5. شغّل فحوصات Flutter أو Supabase المحددة للمهمة.
6. إذا فشل الفحص، أصلح السبب وأعده حتى ينجح؛ لا توثق نجاحًا لم يحدث.
7. بعد نجاح الشرط، حدّث حالة المهمة وسطرًا واحدًا في Progress log.
8. اذكر الملفات التي تغيّرت ونتائج الفحوص. لا تنشئ commit دون أن تطلب المهمة ذلك.

## قواعد ثابتة

- مهمة واحدة فقط من الخطة في كل جولة.
- كل تعديل للبيانات يطابق جدول Supabase وسياسات RLS ودوال SQL وEdge Function ذات الصلة.
- أي نص ظاهر للمستخدم يضاف إلى app_ar.arb وapp_en.arb ثم تُحدّث ملفات الترجمة.
- حافظ على قابلية الاستخدام لكبار السن: مساحة لمس كبيرة، نص واضح، Semantics، ودعم RTL.
- الاختبارات لا تعتمد على شبكة حقيقية؛ استخدم عملاء Supabase وهميين أو مزودات بديلة.
- لا تعتبر MASTER_PLAN.md أو ROADMAP.md دليلًا على تنفيذ ميزة؛ راجع الكود.
