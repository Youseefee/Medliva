# عقد Supabase

هذا المستند يصف الواجهات التي يستخدمها التطبيق الآن. لا يوجد خادم تطبيق وسيط؛ Flutter يتصل بخدمات Supabase باستخدام جلسة المستخدم. يظل PostgreSQL وRLS مصدر صلاحيات البيانات.

## المصادقة

- التسجيل والدخول والخروج وتجديد الجلسة عبر Supabase Auth بالبريد وكلمة المرور.
- يرسل Supabase Flutter الجلسة تلقائيًا إلى Data API وEdge Functions المصادقة.
- الملف الشخصي محفوظ في public.users ومعرّفه يساوي auth.users.id. يقيّد RLS قراءة الملف وتعديله.

## الوصول إلى الجداول

| الجدول | العمليات المستخدمة | نطاق الوصول |
|---|---|---|
| users | قراءة وتحديث الملف الشخصي | المريض نفسه والمرافق المرتبط للقراءة؛ التعديل لصاحب الحساب فقط |
| drug_catalog | البحث عن الأدوية ومطابقة OCR | قراءة وفق سياسات Supabase |
| medications | قراءة، تعديل، وإلغاء تفعيل الأدوية | المريض والمرافق النشط المصرح له |
| schedules | قراءة وإدارة مواعيد الدواء | الوصول المصرح به للدواء المرتبط |
| intake_logs | قراءة سجل الجرعات | المريض والمرافق النشط |
| vitals_logs | قراءة سجل القياسات | المريض والمرافق النشط؛ الكتابة عبر RPC |
| emergency_contacts | قراءة وإدارة جهات الاتصال | المريض والمرافق النشط |
| alerts | قراءة التنبيهات عبر RPC | المريض والمرافق النشط |
| prescriptions | سجل الروشتات إن استُخدم | وفق RLS؛ OCR الحالي لا يحفظ أدوية تلقائيًا |
| caregiver_links | لا تُكتب مباشرة من التطبيق | دوال الاقتران تتحقق من الدور والحالة |
| devices | لا تُكتب مباشرة من التطبيق | التسجيل عبر register_device |
| report_shares | لا تُكتب مباشرة من التطبيق | الإنشاء والتحقق عبر دوال مشاركة التقرير |

## دوال PostgreSQL

تُستدعى هذه الدوال من Flutter عبر Supabase RPC، وتطبق فحوص الدور والارتباط المطلوبة:

| الدالة | الغرض |
|---|---|
| create_medication_with_schedules | إنشاء دواء ومواعيده بعملية ذرية |
| record_intake_log | تسجيل الجرعة ومعالجة التكرار والمخزون؛ يُستخدم أيضًا لمزامنة الطابور |
| record_vital | حفظ قياس وحساب مستوى التنبيه وإنشاء تنبيه حرج عند الحاجة |
| generate_caregiver_pairing_code | إنشاء رمز ربط مؤقت للمريض |
| consume_caregiver_pairing_code | استهلاك رمز المريض وربط المرافق |
| list_patient_caregivers | عرض المرافقين المرتبطين بالمريض |
| get_caregiver_dashboard | ملخص المرضى والجرعات للمرافق |
| trigger_sos | إنشاء تنبيه استغاثة والتحقق من الحساب |
| list_patient_alerts | جلب التنبيهات المحفوظة والجرعات المتأخرة ضمن صلاحية المستخدم |
| register_device | تسجيل جهاز المستخدم دون منح كتابة مباشرة إلى جدول الأجهزة |
| create_report_share | إنشاء رمز مشاركة عشوائي محدود الصلاحية وتخزين بصمته |
| get_public_report | جلب التقرير بالرمز؛ متاح لدالة Edge بصلاحية الخادم فقط |

## Edge Functions

| الدالة | المصادقة | الاستخدام |
|---|---|---|
| scan-prescription | JWT مطلوب | قراءة صورة من bucket خاص وكتالوج الدواء باستخدام جلسة المستخدم؛ استدعاء Gemini وإرجاع اقتراحات للمراجعة |
| public-report | رمز مشاركة مؤقت | التحقق من الرمز والانتهاء والإلغاء، ثم إرجاع ملخص التقرير |

يُرفع ملف الروشتة أولًا إلى bucket prescriptions الخاص. لا تُنشئ نتيجة OCR دواءً قبل مراجعتها وتأكيدها في Flutter. مفتاح GEMINI_API_KEY محفوظ كسر في Supabase، ومفتاح secret/service_role لا يوضع في التطبيق.

## التخزين

- pill-images وprescriptions مخزنان خاصان.
- تُحفظ الملفات داخل مجلد بمعرّف المريض.
- سياسات Storage تسمح للمريض والمرافق ذي الارتباط النشط فقط.
- يستخدم التطبيق روابط موقعة لعرض الملفات الخاصة.
